What happens to your data

On our server

  • PDF files (teachers). When a teacher converts a PDF, the file is sent through our server to an AI service (Anthropic) that reads it and returns the exercises. Vocabloom does not keep the PDF.
  • Converted worksheets. The exercises that come back from the AI (text only, never the PDF) are kept for [7] days under a fingerprint of the PDF, so converting the same file again does not use the AI again. They are kept in the shared storage if the school has switched it on, and otherwise only in the memory of a running server, where they disappear when that server stops. This can be switched off.
  • Short links and QR codes (optional storage, teachers choose). Only if a teacher presses Create short link and QR code, a copy of that worksheet is kept for [90] days so the link can be short. When a student opens a short link, the phone asks our server for that worksheet, so the server and the hosting provider see that request (link, IP address and time). Normal links do not do this.
  • Usage counters. To stop abuse and control costs, the server counts requests, wrong access codes and conversions per day (in the shared storage if there is one, otherwise in the server’s memory). Counters are labelled with a scrambled form of the visitor’s IP address (a keyed hash), never the address itself, and for conversions with the name the school gave to that teacher’s code (for example “anna”). They expire after at most two days.
  • Access code (teachers). The code is kept in the browser tab only while it is open (session storage) and is sent with each request to check that you may use the tool.
  • Hosting logs. Our hosting provider ([hosting provider]) may record technical data such as IP address and time of each request, for security and to keep the service running.

Vocabloom never receives a student’s name, answers, score, review deck or reading history.

Only on a student’s own device

  • Worksheet links. A normal share link stores the worksheet inside the link itself, in the part after the #. That part is not sent to our server when a student opens the link.
  • Answers. A student can type a name and answer the exercises. Name, answers and progress stay in that device’s browser (local storage) so the student can continue later. Teachers cannot see them.
  • Review deck (the student chooses). If a student presses Save to my review deck, the questions they got wrong are kept in that device’s local storage, with the worksheet’s title, and come back on later days. Nothing is sent. Without that choice nothing is kept.
  • Recent worksheets. The app remembers the title and link of the last few worksheets opened, so they can be found again.
  • Offline copy. The browser keeps a copy of the app, and of worksheets opened through short links, so they open without a connection.
  • Listen buttons. The buttons that read a question aloud use the voices that come with the phone or browser. Only the worksheet’s own text is read, never a student’s name or answers, and Vocabloom prefers voices that run on the device. Some browsers offer an online voice run by the browser’s maker: if the student’s browser chooses one, the text of that question is processed by that company.

Deleting it. On the home page (My review deck), Delete my deck removes the deck and Clear everything on this device removes answers, deck and recent worksheets. Clearing the site data in the browser removes everything, including the offline copy. On a shared computer, please clear it when you finish.

Vocabloom sets no cookies, uses no analytics or advertising, and loads no fonts or scripts from other companies.

Artificial intelligence

An AI service reads the teacher’s PDF and builds the exercises. It may also write the hints and explanations that students see, and the student pages say so. The AI can make mistakes, so teachers are asked to check every exercise, answer, hint and explanation before sharing the link. Vocabloom makes no automated decisions about students: the score is feedback for practice and is not stored or sent anywhere.

Children and young people

Students may be under 16 or under 18. The school remains responsible for them and decides how the link is shared (for example inside its own virtual classroom). Vocabloom asks for no account, email address or other identifier: a name is optional and stays on the student’s device, and so does the review deck. How the data is protected

Connections are encrypted (HTTPS). The tool uses strict browser security rules, limits repeated wrong access codes and conversions, checks everything the AI returns before showing it, keeps no student accounts and no student answers on any server, and stores IP addresses only in scrambled form. Security problems can be reported as described in the project’s security policy (see /.well-known/security.txt).
